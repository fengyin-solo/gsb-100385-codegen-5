# 田野考古发掘数字化管理系统

面向考古发掘现场探方管理、地层记录、遗迹测绘、遗物登记、浮选采样与测年送检全流程的田野考古数字化管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `field-archaeology-digital:entries` 这一项，或调用 `resetModule(模块)`。

## 出土遗物外业交换封包

没有网络和后端时，工地设备与室内设备之间用离线文件交接出土遗物，入口在「出土遗物」页面。

- **挑选与导出**：按器物编号、所属发掘区、出土层位（片段包含）和登记状态（精确匹配）筛选，
  生成 `出土遗物外业封包-<时间>.json`。封包内含格式版本、来源设备、筛选条件、记录数组，
  以及两级 SHA-256 摘要：封包整体一个 `checksum`，每条遗物一个 `recordHash`
  （只覆盖业务内容，不含行 id 与版本元数据）。摘要按 key 排序后规范化序列化计算，
  用浏览器自带 Web Crypto 完成，完全离线。
- **导入校验**：先校验封包标识与格式版本，再复核整体摘要，最后逐条复核 `recordHash`。
  任一项不过关整包拒绝，一条数据都不落库。
- **幂等**：遗物身份以器物编号（业务键）为准，行 id 只用于本机展示。导入是
  upsert：本地没有才新增，已有则走版本裁决，同一封包反复装载不会多出遗物；
  内容与本地完全一致时零写入。导入台账记在 localStorage 的
  `field-archaeology-digital:packet-ledger`，重复封包会在报告里明确标出。
- **不跳过现场修改**：封包记录与本地内容不一致时不会静默跳过，裁决结果
  （新增 / 按封包更新 / 保留本地 / 一致未写入）逐条列在导入报告里。
- **版本冲突裁决依据**（实现选择，明确如下）：每条遗物带单调递增的现场修订版本号 `_rev`
  和最近修改时间 `_updatedAt`，每次状态流转自动 +1。
  1. `_rev` 高者胜——版本号代表这条记录基于更多次现场修改，是主依据；
  2. `_rev` 相同（两台设备各改一次、或旧封包回流）时，修改时间更晚者胜；
  3. 两者都相同（含缺少时间）时**保留本地**：室内端已做的清洗、编号、入库劳动，
     不应被一个无法证明自己更新的外业封包静默覆盖；覆盖后的 `_rev` 取双方最大值。
  封包格式版本（`packetVersion`，当前 1）与本机不一致时直接拒绝导入，不做猜测兼容。

### 办理入库的跨模块事务

「办理入库」一次动作同时写两个模块：出土遗物状态变为「已入库」，库房目标架位的
当前件数 +1、可用空间（容纳件数 − 当前件数）同步重算，放满时架位状态自动翻成「已满」；
已满或临时封存的架位不能选。所有校验先在内存完成，再由
`saveRowsTransaction` 单点写入 localStorage：序列化/配额失败时不换内存缓存，
遗物状态与架位件数两边一起退回，不会出现「已入库但架位没加件」的中间态。

行为验证脚本：`cd frontend && node scripts/verify-packet.mjs`（覆盖筛选导出、
摘要防篡改、重复装载幂等、四种冲突裁决、入库联动与写入失败回退，共 33 项断言）。
